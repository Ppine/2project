# 시연용 테스트 명세서

웹 대시보드의 **내 명세서 올리기**로 올려 보는 파일들입니다. 4가지 형식을 2개씩 준비했습니다.
금액은 `docs/service fee modified.csv`의 실제 요금을 썼고, 카드·계좌번호는 모두 가린 가짜 번호입니다.

다시 만들기: `uv run --no-project --with pillow python data/samples/generate_samples.py`

| 파일 | 형식 | 기간 | 거래 |
| --- | --- | --- | --- |
| `1_card_single_a.csv` | 카드 1장 | 2026.04–09 | 138건 |
| `1_card_single_b.csv` | 카드 1장 | 2026.05–10 | 128건 |
| `2_card_multi_a.csv` | 카드 3장 섞임 | 2026.04–09 | 121건 |
| `2_card_multi_b.csv` | 카드 3장 섞임 | 2026.05–10 | 123건 |
| `3_card_transfer_a.csv` | 카드 + 계좌이체·자동이체 | 2026.04–09 | 144건 |

## 형식

- **1·2번**: 기존 카드 명세서 형식 `이용일자, 이용카드, 가맹점명, 이용금액, 승인번호`. 2번은 `이용카드` 열에 카드 3장이 섞여 있습니다.
- **3번**: 가계부 앱에서 내보낸 지출 내역 형식 `거래일자, 구분, 결제수단, 내용, 금액, 메모`. `구분`은 카드결제·계좌이체·자동이체입니다.
- **4번**: 이미지는 Gemini가 화면을 읽어 날짜·내용·금액을 뽑습니다. 입금(+)은 빼고 지출만 저장합니다.
  - `.env`에 `GEMINI_API_KEY`가 있어야 하고, 한 장에 20~40초쯤 걸립니다.
  - **이미지 전체가 Google로 전송됩니다.** 실제 캡처를 올릴 때는 잔액·계좌번호가 함께 넘어간다는 점에 주의하세요.

## 엔진 동작 참고

- 금액이 구독료 표와 같다는 이유만으로 확정하는 것은 PG사·앱마켓·공유 대행사 결제(`NICE페이`, `APPLE.COM/BILL`, `피클플러스` 등)뿐입니다. 이름이 있는 직접 결제는 이름이 맞아야 확정합니다.
- 구독료 표의 `결제경로` 열로 앱마켓 요금(`app_store`·`google_play`)과 공유 요금(`share`)을 나눕니다. 앱마켓 요금은 그 앱마켓 결제에서만, 공유 요금은 같은 대행사 결제에서만 후보가 됩니다.
- `이체 `·`송금 `으로 시작하는 반복 이체는 `최대인원`이 있는 요금을 n명이 나눈 몫(1·10·100원 단위 올림·내림)과 비교해 낮은 신뢰도 후보만 냅니다.
- 계좌이체 고정비(월세·통신비·보험)도 '구독'으로 집계돼 월 합계가 커집니다(3a는 월 608,230원).
- **Gemini 무료 등급은 하루 요청 수가 적습니다**(테스트 때 하루 20회에서 429). 이미지 1장과 처음 보는 반복 결제 1건이 각각 1회입니다. 한도를 넘으면 이미지는 업로드에 실패하고, 출처 추론은 규칙 기반 결과만 보여줍니다.
